# Changelog

Rule changes change outputs, so every new or changed rule is at least a minor version bump (ADR-09).

## Unreleased (next minor version)

Checkmarx version policy and purl handling. Design and sources: `docs/checkmarx-version-purl-fix.md`.

- **New command `cdxgen-fix`** (`sbom_fixer/cdxgen.py`, `sbom_fixer/ecosystem.py`): step 1 turns any SBOM into CycloneDX in cdxgen layout (SPDX 2.2/2.3 -> CycloneDX 1.6 with packages, purls, licences, hashes, dependency relationships and root; CycloneDX keeps its version; bom-ref = purl when missing; one dependencies entry per component) and writes `<name>.cdxgen.cdx.json`. Step 2 runs `fix` with the canonical form and writes `Copilot_SBOM.json` (`--name`). `metadata.tools` names the generator of the detected ecosystem (nuget -> cyclonedx-dotnet, maven -> cyclonedx-java, npm -> cyclonedx-node, pypi -> cyclonedx-python, ...): majority of the component purl types, ties to the root component, then the generator name; `--ecosystem` forces it. The converted file is validated against its schema and the errors are listed (output and report `validation`) before step 2 repairs them. No purl or bom-ref in the output holds a web URL: purls written as a URL (also SPDX locators, URL bom-refs, the root component) become the registry purl, now also for package pages (www.npmjs.com, pypi.org/project, mvnrepository.com, crates.io, packagist.org, hex.pm, rubygems.org, pkg.go.dev, nuget.org/packages); a URL in a name or qualifier never reaches the purl (CXN-020), URL bom-refs are replaced and renamed in dependencies (CXN-040). New canonical profile keys `tool_per_ecosystem`, `ecosystem_tools`, `ecosystem` (off by default, so `fix` is unchanged). Report `<name>.cdxgen.report.json`. Tests: `tests/test_cdxgen.py`.

- **Checkmarx canonical form (CXN-\*), on by default for `checkmarx` and `checkmarx-cli`.** Schema-valid files that the old `fix` reported as "unchanged" (for example the cyclonedx-gradle-plugin SBOM `ratecard-sbom.json`) were still not ingested by Checkmarx. After the repair, the Checkmarx copy is now reduced to the cyclonedx-dotnet layout that ingests reliably: top level `bomFormat, specVersion, serialNumber, version, metadata, components, dependencies` (CXN-010); metadata `{timestamp, tools, component}` with the tool list from the profile, default AppThreat cyclonedx-dotnet 0.8.0 in the array form (CXN-011); nested components flattened, also under metadata.component (CXN-001); every component has a purl `pkg:type/[namespace/]name@version`, qualifiers and subpath removed, missing purls built from the bom-ref or the generator's ecosystem, else `pkg:generic/<name>@<version>` (CXN-020); licences reduced to id/name/expression, `NOASSERTION` when empty (CXN-030, as licence `name` because NOASSERTION is not in the schema's SPDX id list); components reduced to `bom-ref, type, name, version, purl, licenses` (CXN-040); dependencies only between existing components, no self-references, duplicates merged (CXN-050). The spec version never changes and the output is validated against it. Profile section `canonical:` (`enabled`, `tools`, `component_fields`, `default_license`, `keep_purl_qualifiers`, `purl_fallback`); CLI `fix`/`check --no-canonical`. The `compliance` profile and SPDX files are not affected. Tests: `tests/test_canonical.py` (whole corpus + rules); the repair-layer tests run with `canonical` off. `wheelhouse/sbom_fixer-1.0.0-py3-none-any.whl` rebuilt.
- **`fix` no longer downgrades.** Every profile repairs on the file's own schema version (`allow_downgrade: false`). Errors no repair rule fixes are resolved on the same schema: COERCE-001 converts a wrong JSON type when the meaning is clear, COERCE-002 removes a value the schema rejects (DATA_LOSS). A version not in `accepted_versions` is kept with the finding VER-KEEP. The old descent is opt-in with `--allow-downgrade` (fix, check) or `allow_downgrade: true`; it now also coerces at each level, so it steps down only for files the consumer does not accept. CycloneDX 1.8+ still maps to 1.7 (no schema exists). CycloneDX 1.2 is accepted by the checkmarx profiles (Checkmarx lists 1.0-1.6) and fixed at 1.2.

- **New commands `fill-required` and `fill-all`** (`sbom_fixer/complete.py`): take any JSON (missing markers, a bare list, unknown or 1.8+ versions), derive required fields, apply the fix repair rules at that version, then add every required (or every schema) field: derived where a rule allows, otherwise a standard/default/enum value or an obvious PLACEHOLDER. Values the schema rejects are converted ("no" -> false, "42" -> 42, string -> {name}) or removed and refilled. Identity fields and references are never invented. Report: `<name>.fill-<mode>.<cdx|spdx>.report.json`. Tests: `tests/test_complete.py`.
- **Large SBOMs:** progress lines on stderr for `fix` and `fill-*` (auto from 1 MB, `SBOM_FIXER_PROGRESS=1/0`). `fill-*` validates the large output twice instead of four times, caches schema lookups and builds paths lazily (5,000 components: `fill-all` about 3.5 min -> under 1 min). Reports group entries by path pattern above 5,000 (283 MB -> 0.3 MB). `fill-all` no longer leaves empty objects, which `fix` (SAN-002) stripped and which then made oneOf parents invalid and pushed the file down a version.

- **Versions:** profile `checkmarx` accepts CycloneDX 1.3-1.7 and repairs 1.6 and 1.7 at their own version (1.7 provisional: the Checkmarx "Scanning SBOMs" page lists 1.0-1.6). New profile `checkmarx-cli` for the `cx` CLI (used by the Jenkins stage) with the same versions: 1.6 and 1.7 are kept in every profile. If a cx version rejects 1.7, cap one run with `--accepted 1.3,1.4,1.5,1.6`. Generator hints in the notes now name the actual target version instead of always 1.5. `wheelhouse/sbom_fixer-1.0.0-py3-none-any.whl` rebuilt (the old wheel still had the 1.3-1.5 profile). A wheel install run from the checkout finds `tools/sbomqs` in the current folder.
- **Future versions:** new spec keys `max_version` and `future_versions` (`reject` default, `downgrade`). CycloneDX 1.8+ is brought down to `max_version` by a generic future hop; CycloneDX 2.x is refused (VER-002 in the reason).
- **Rules added:**
  - Future hop: CDX-FWD-001, CDX-FWD-002, CDX-FWD-003.
  - Sanitizers: SAN-009 (purl written as a URL), SAN-013 (default tool when none is named, profile key `ensure_tools`).
  - Checkmarx purl (profile section `purl:`): CXP-001, CXP-002, CXP-003, CXP-004, CXP-005, CXP-010, CXP-011, CXP-012, CXP-013, CXP-020, CXP-021, CXP-030, CXP-051.
- **Changed:** SAN-012 runs only for profiles without a `purl:` section. SAN-090 no longer adds sbom-fixer to metadata.tools twice. The NTIA "Unique identifier" check counts a purl only when it parses.
- **Outputs:** `<name>.<profile>.purl-coverage.csv`; `checkmarx_coverage` (before/after) in changes.json; notes sections 4 and 6 show Checkmarx coverage, coverage by purl type and the expected package count.
- **Exit code 7:** no component has a purl type the profile supports (Checkmarx would fail the scan). `fix --verify` skips the upload then, and uses the supported-component count as the default `--expected-packages`.
- **Corpus:** `corpus/future/` and `corpus/purl/` (9 new files); `expected.yaml` updated for the 1.6/1.7 policy.
- **sbomqs offline:** sbomqs 2.1.2 vendored in `tools/sbomqs` (Windows x64 binary, Linux x64 archive, upstream `checksums.txt`, `SHA256SUMS`, Apache-2.0 `LICENSE`) by the new `tools/vendor_sbomqs.py`, which verifies the release checksums. Lookup order: `SBOMQS_BIN`, `tools/sbomqs`, `PATH`. The Dockerfile no longer downloads sbomqs (was 1.0.0 from GitHub); it extracts the vendored 2.1.2 archive after a sha256 check. `audit` prints the grade and the binary; sbomqs errors are shown without colour codes and timestamps. `.gitattributes` keeps `tools/sbomqs` byte-for-byte. New tests: `tests/test_sbomqs_vendored.py`.
- **Docs:** `SBOM_Fixer_Rule_Book_And_Installation_guide.docx` (and `docs/SBOM_Fixer_Rule_Book.docx` / `.md`) updated: Step 13.1-13.6 on the bundled sbomqs, 17.5 upgrading sbomqs, and the 1.6/1.7 policy, `checkmarx-cli`, exit 7, purl coverage and the regenerated rule list.

## 1.0.0 - 2026-10-02

First release. All eight phases of the implementation plan.

- **Core:** offline schema registry (CycloneDX 1.2-1.7, SPDX 2.2.2 and 2.3), encoding/format/version/generator detection, validation with JSON Pointer paths and grouped causes, hybrid fast validation (fastjsonschema pre-check, jsonschema for exact errors) with O(n) `uniqueItems` and a fast IRI checker.
- **Version descent (ADR-02):** start at the declared version, repair, accept or step down one version, down to the floor. Oracles: `profile`, `checkmarx` (real upload per level, cached, budgeted), `schema-only`.
- **Rules added:**
  - Same-version repair: REP-001, REP-002, REP-003, REP-004, REP-005, REP-006, REP-007, REP-008, REP-009, REP-010, REP-011, REP-012.
  - CycloneDX 1.7 -> 1.6: CDX17-001, CDX17-002, CDX17-ENUM.
  - CycloneDX 1.6 -> 1.5: CDX16-001 to CDX16-011.
  - CycloneDX 1.5 -> 1.4: CDX15-001 to CDX15-011, plus CDX15-001P (importer-specific tools form).
  - CycloneDX 1.4 -> 1.3: CDX14-001 to CDX14-004.
  - SPDX 2.3 -> 2.2: SPDX23-001, SPDX23-002.
  - Sanitizers: SAN-001, SAN-002, SAN-003, SAN-004, SAN-010, SAN-011, SAN-012, SAN-020, SAN-021, SAN-022, SAN-030, SAN-031, SAN-050, SAN-060, SAN-090.
  - Pipeline IDs: ENC-001, ENC-002, ENC-003, CDX-VER, SPDX-VER, PRUNE-001.
- **Outputs:** fixed SBOM (UTF-8, no BOM), JSON Patch, human diff, change log JSON, notes.txt, quality JSON.
- **Audit:** built-in NTIA 2021 checker (CycloneDX and SPDX), sbomqs wrapper, quality gate (exit 4), framework checks for NTIA, CISA FSCT minimum level and BSI TR-03183-2 v2 basics.
- **Profiles:** `checkmarx` (provisional accepted versions, ADR-01) and `compliance` (`floor: declared`, never downgraded).
- **CLI:** `check`, `fix` (several profiles, `--verify`, `--verify-each-step`), `audit`, `schema-diff`, `verify`, `bisect`, `rules`.
- **Checkmarx:** `cx` CLI client behind an interface; credentials only from environment variables; nightly corpus job.
- **Distribution:** Dockerfile with pinned sbomqs, Jenkins stage, nightly job, repository CI.

Known limitations: CycloneDX XML input, SPDX tag-value/RDF/3.0, upgrade hops (1.2 -> 1.3), REP-013 and REP-014 are not implemented. Checkmarx accepted versions are provisional until `docs/checkmarx-matrix.md` is filled in.
